# Client context-window guard — 2026-10-23

The installed Claude Code 2.1.269 assumes 200,000 tokens for the custom `copilot-auto` ID, rather than assuming 1M. This was seen in prior interactive warnings and JSON `modelUsage.contextWindow`. Copilot's selected gpt-6-luna advertises a larger total window but a separate 872,000-token prompt limit; other catalog entries advertise smaller prompt windows. A universal fivefold multiplier would be inaccurate and would corrupt usage statistics.

The bridge now discovers the window directly from Copilot. Before launch or environment-copy, an authenticated `/api/context` request refreshes Copilot `/models` and resolves `/auto` when needed. Auto metadata discovery is cached for at most five minutes and never beyond the returned session expiry. Limits use the smaller valid `max_context_window_tokens` / `max_prompt_tokens` values for configured slots, an explicit CLI model and Auto selections observed by the server. An unrelated picker model does not shrink the active model's window. Fresh catalog limits can lower an older Auto observation. Hidden catalog entries alone do not establish Auto entitlement.

There is no default fixed ceiling. `contextWindowTokens` is an optional user cap; `contextFallbackTokens` (default 200,000) applies only to missing metadata. The status API exposes the source (`copilot` or `fallback`), model IDs, bounds and fetch time without session tokens. Missing limits generate a CLI warning. Limits are bounded at the installed Claude client's supported 1M override range; that is a client restriction, not a claim about Copilot. API authentication/network failures are not relabeled as missing metadata. The dashboard polling loop reads cached status and does not make periodic upstream probes.

The child environment sets `CLAUDE_CODE_MAX_CONTEXT_TOKENS`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, and `CLAUDE_CODE_DISABLE_1M_CONTEXT`. It clears inherited flags disabling compaction or unknown-model-window enforcement. The explicit auto-compact window also bounds proactive compaction for recognized model IDs where the maximum-context override alone does not apply. The auto-compact setting has a 100k minimum; unknown smaller IDs still use the declared smaller model window. Claude's own reserved-output/headroom rules remain in charge. See [official model/window configuration](https://code.claude.com/docs/en/model-config#correct-the-window-for-a-gateway-or-custom-model-id).

No token usage, cache counts, premium metrics or count_tokens values are multiplied. No context/history is silently truncated by the proxy. Real provider overflow remains mapped to Anthropic 400 invalid_request_error / prompt is too long so native recovery can run.

## Limits

Settings are applied when launching a Claude process; they cannot retroactively alter another already-running process. The installed CLI's gateway list discovery reads model names, not per-model context overrides; its dynamic model-config fetch is disabled in the installed build, as verified in its local source. We therefore do not claim that extra `/v1/models` limit fields update an active session. Restart Claude through the updated launcher to apply discovery. Auto's preflight prompt can select differently from an actual user prompt. Later Auto selection, manual `/model` changes, hidden provider prompt overhead, tokenizer differences or large tool results may still exceed upstream limits. The recognized too-long error recovery remains necessary. Managed settings can also override user settings.
